Create and save today's work plan in 247C. This is the user's standing instruction for a separate planning conversation every Monday through Friday at 07:30 in Europe/Athens. Work autonomously within this planning scope. Do not create another automation or start task workers.

1. Determine today's date and weekday in Europe/Athens from the current clock. Use that date throughout this run. On a weekend, make no changes. Read the existing day using `c247_day` before preparing any changes. Respect its notes, capacity, meetings, existing entries, completed steps and removed entries.
2. Refresh the configured calendar through 247C's `calendarSync` RPC when calendar import is available. Read `calendarState` until the refresh completes or fails, with a bounded wait of at most 90 seconds, then read the day again. If refresh is unavailable or fails, retain the saved meetings and disclose their freshness. Never create a task to represent a meeting or change meeting times.
3. Read open tasks with `c247_tasks` and inspect the accepted dossiers of relevant candidates with `c247_read`. Check the previous seven calendar days with `c247_day` for unfinished daily steps, including Friday and any weekend work. Carry forward only relevant unfinished work on tasks that are still open. Do not copy the entire backlog. Pending or rejected proposals are not accepted task context.
4. Select a short, achievable set of concrete next actions. Prioritize explicit commitments and deadlines, urgent and important work, actionable follow-ups, and important work that would otherwise be deferred. Use meetings and any saved daily capacity to limit the number of tasks; when capacity is unknown, aim for at most three focus tasks in total, counting existing open plan entries. If a coherent plan is already saved, add only a clearly missing time-critical commitment. A retry is not a reason to add another batch of lower-priority tasks. Include a waiting task only when it has an actionable follow-up. Do not invent deadlines, dependencies or an obligation to finish every open task today.
5. Save missing tasks directly to the day using `c247_plan_add`, with the full task ID, today's date, a stable UUID requestId, and a concrete `step` grounded in accepted task context. Add higher-priority actions first. Preserve all existing day entries, their order, text, states and manual choices. Skip any task already represented today, including removed or completed entries. Do not mark earlier entries carried, done or removed. Reread the day before writes, reuse requestIds for identical retries, and reread after a conflict instead of overwriting concurrent edits.
6. Do not supply plannedMinutes or reportedMinutes when adding a task. This planning instruction authorizes selection and daily steps, not guessed manual hours. Preserve all saved planned, actual and reported values, including zero and blank. Actual remains measured and read-only; automatic reported estimates and meeting accounting remain with their existing 247C processes. Do not change task fields, accept proposals, create tasks, send messages to other people or execute the selected work.
7. Read the saved day back and verify the additions. Finish with a concise update in the user's preferred language: the date, the main priorities and their next actions, meetings or capacity constraints, and any missing information or failed saves. Distinguish saved entries from suggestions. If a plan already exists, report the additions or that no changes were needed. Do not claim a plan was saved when the tools failed. Preserve existing records and quotations in their original languages.

Use native 247C tools when available. If this BB provider does not expose them, `bb 247c list --json` and `bb 247c show <task-id> --json` provide accepted task context. The plugin's schema-validated RPC endpoints can read and update the day without database access:

- POST `/api/v1/plugins/247c/rpc/day` with `{ "date": "YYYY-MM-DD" }`.
- POST `/api/v1/plugins/247c/rpc/calendarSync` with `{ "date": "YYYY-MM-DD" }`, and `/calendarState` under the same RPC prefix with `{}`.
- POST `/api/v1/plugins/247c/rpc/dayAdd` with `{ "requestId": "<UUID>", "date": "YYYY-MM-DD", "taskId": "<full task ID>", "step": "<next action>" }`.

Use BB_SERVER_URL from the environment, or the local BB default `http://127.0.0.1:38886`, with Content-Type application/json. Require `ok: true` and read `result` in each response. Use these endpoints only for the planning operations above; do not edit SQLite, provider settings or authentication. If both native tools and the supported RPC path are unavailable, leave the plan unchanged and report the concrete error.
