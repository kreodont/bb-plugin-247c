# Бэкап и восстановление 247C

Утилита `tools/backup.py` использует Python 3.11+ и стандартную библиотеку. Для создания полного архива должны работать BB и 247C; `bb` должен быть доступен. Снимок SQLite создаётся через [Online Backup API](https://www.sqlite.org/backup.html), включая подтверждённые изменения WAL. Простое копирование работающего `data.db` для этого не используется.

## Что входит

- Согласованный снимок всей базы 247C: задачи, поля, факты, предложения, подтверждения, знания, журнал времени, календарь и сохранённые выгрузки.
- Исходники и сборка установленной версии; источники используемых локальных плагинов провайдеров.
- Настройки плагинов без секретных полей.
- Архив событий связанных с 247C тредов BB, включая открытые разговоры, и текстовые артефакты, ранее сохранённые в 247C.
- Версии, контрольные суммы, счётчики таблиц и автономная копия `restore.py`.

В архив не входят входы OAuth, Связка ключей, данные других приложений и произвольные файлы из рабочих папок. Вложения или файлы, на которые чат лишь ссылается, требуют своего бэкапа. Импортированные Markdown-документы уже содержатся в базе целиком. SQLite и история BB снимаются последовательно, поэтому у них отдельные моменты фиксации.

## Создать копию

Узнай расположение данных через `bb status --json`. В примере ниже используется стандартная папка `~/.bb` и уже подключённая папка Google Drive. Для каждой независимой установки используй отдельную подпапку и `--machine`.

```sh
python3 tools/backup.py create --data-dir "$HOME/.bb" \
  --destination "/path/to/Google Drive/247C/backups/my-mac" --machine my-mac
```

Архив сначала собирается и проверяется локально, затем одним ZIP-файлом копируется в папку назначения с проверкой SHA-256. Временный файл получает суффикс `.partial`, окончательное имя появляется после завершения копирования. Результат записывается в `latest-<machine>.json`.

`--daily` предотвращает повторный успешный бэкап в тот же день (Europe/Athens, можно поменять через `--timezone`). `--retention` оставляет копии за последние 90 дней: за последние 7 дней сохраняются и дополнительные ручные снимки, затем остаётся последний снимок за день. Удаляются только архивы этой машины с форматом имён утилиты, после успешного нового снимка со всей доступной историей.

Планировщик ОС может запускать эту команду ежедневно. На macOS пример LaunchAgent создаётся командой `python3 tools/schedule_macos.py --help`. Время задания — локальное время Mac. При выключенном или спящем компьютере фактическое выполнение зависит от планировщика ОС и доступности Drive. Ошибки пишутся в отдельный журнал; устаревший `latest` означает, что новую копию необходимо проверить.

Папка Google Drive должна принадлежать нужному личному аккаунту и не быть общей. Архив содержит личные/рабочие тексты. Код публикуется в GitHub отдельно; бэкапы туда не попадают. На macOS утилита дополнительно проверяет статус загрузки через File Provider Google Drive и записывает `cloudUploadVerified`. Если статус недоступен или загрузка ещё идёт, проверь синхронизацию Drive и наличие файла в веб-интерфейсе; локальная контрольная сумма сама по себе не подтверждает облачную загрузку. Для полной независимости от Google можно дополнительно копировать готовый ZIP на другой носитель.

## Проверить и восстановить

```sh
python3 tools/backup.py verify /path/to/247c-snapshot.zip
python3 tools/backup.py restore /path/to/247c-snapshot.zip --destination /new/recovery-folder
```

Если компьютер потерян, скачай ZIP из Drive. В нём есть `restore.py`, который выполняет те же команды; исходная установка не нужна. Папка восстановления не должна существовать. Проверяются все файлы, структура ZIP, целостность SQLite и связи таблиц.

`database/data.db` сохраняет исходный снимок без изменения. `prepared-bb/plugins/247c/data.db` подготовлена для новой установки: незавершённые сессии помечены как требующие нового разговора, активные проверки остановлены. Задачи, факты, принятия и время не меняются. Параметры автоматического запуска в `settings/247c.for-restore.json` отключены до первого ручного запуска.

1. Установи совместимый BB, необходимые провайдеры и код из `plugins/247c` (для установки из исходников сначала `npm ci --include=dev`, затем `bb plugin install .`).
2. На новой установке с пустой базой выполни `bb plugin disable 247c`. Убедись через `bb plugin list`, что плагин отключён.
3. Скопируй подготовленную базу в `<dataDir>/plugins/247c/data.db`. Не копируй её поверх работающей или непустой установки: сначала отдельно сохрани существующие данные.
4. Примени сохранённые несекретные настройки через `bb plugin config`. Включи плагин командой `bb plugin enable 247c`. Войди в провайдеры и выбери новые рабочие папки.
5. Сравни число задач, знания и план дня с `manifest.json`. Прежние BB thread/host/environment ID являются историческими ссылками: архив `threads/` доступен для чтения, но прежний агентский процесс не продолжается. Работу начинай новым разговором.
6. Проверь источники вручную. После этого включи `hourlyUpdates`, если нужен расписанный сбор, и настрой ежедневный бэкап уже с именем нового компьютера.

`RESTORE-REPORT.json` перечисляет подготовленные файлы и дальнейшие действия. Утилита восстановления сама не меняет работающий BB и не выполняет код из архива.
